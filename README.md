# DeepSeek Code Agent

A local-first VS Code coding agent that uses an existing, signed-in DeepSeek chat tab as its reasoning provider. It does not ask for DeepSeek credentials, read browser cookies, or call a paid model API. Normal DeepSeek replies appear verbatim in VS Code. For coding changes, DeepSeek can return a Python script named `fix.py`; the extension previews that workspace-root file and asks before running it.

## Architecture

- `extensions/vscode` is the VS Code sidebar, workspace context collector, review/apply controller, command runner, conversation store, and loopback HTTP bridge.
- `extensions/browser` is a Chromium Manifest V3 extension. Its service worker pairs with the local bridge, receives the validated conversation URL with each task, and reuses or navigates one official DeepSeek tab. `src/adapter.ts` contains website-specific selectors and interaction code.
- `packages/protocol` defines the structured and Python response formats, bridge messages, prompt instructions, and provider-side validation.
- The browser bridge listens only on `127.0.0.1`. VS Code displays a one-time pairing code; the browser popup exchanges it for a random bearer token stored in extension-local storage. VS Code keeps the matching token in SecretStorage so the paired extension can reconnect when **Auto connect** is enabled. Manual mode does not use the saved token after a restart; switching Auto connect back on restores the saved pairing. Initial one-time pairing remains required. Requests have UUID correlation IDs, bounded sizes and timeouts. Neither component handles website credentials or cookies.

The **DeepSeek conversation** toolbar menu in the VS Code chat lets you save the conversation URL and choose whether to reconnect automatically after the first pairing. No conversation is preselected: save a URL you chose from your signed-in DeepSeek session before sending a task. The URL is also available as `deepseekCodeAgent.conversationUrl` in VS Code Settings. Only HTTPS conversation links on the exact `chat.deepseek.com` origin with a UUID chat ID are accepted. The URL is sent to the browser extension with each task and is not stored in browser-extension settings. Before each prompt, the browser extension finds or opens that URL, verifies the loaded tab URL, and waits for the chat input to be available. This confirms that the configured page is ready, not that DeepSeek restored the expected visible history; inspect the conversation in the browser when selecting its link. While collecting an answer, the browser extension clicks DeepSeek's visible **Continue** control whenever it appears and waits for the continued text before returning the response. Pairing, page/input readiness, and a completed response are reported separately. Website layout changes, sign-in requirements, unavailable tabs, navigation failures, and timeouts are surfaced instead of silently falling back. DeepSeek can change its website without notice; selectors are isolated in `extensions/browser/src/adapter.ts` and must be maintained if that happens.

## Requirements

- Node.js 22 or later and npm.
- VS Code 1.97 or later.
- Chromium-based browser with access to the official DeepSeek chat website.
- An existing authenticated DeepSeek browser session. Sign in on the DeepSeek website yourself; do not enter credentials in this project.

## Install and run locally

From the repository root:

```sh
npm install
npm run build
npm test
npm run lint
```

1. In VS Code, open **Extensions: Install from VSIX** after packaging below, or launch a development window with:

   ```sh
   code --new-window --extensionDevelopmentPath="<absolute path to repository>/extensions/vscode" "<absolute path to your project>"
   ```

2. In that VS Code window, open a trusted project folder and select **DeepSeek Agent** in the Activity Bar. Initial browser pairing always requires the one-time code shown in the sidebar; **Auto connect** only restores a pairing after that initial approval.
3. In Chromium, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select `extensions/browser/dist`.
4. Open the **DeepSeek conversation** menu in the VS Code chat, enter and save the signed-in conversation URL, and choose the browser reconnection preference. Inspect the selected conversation in the browser yourself; a URL cannot prove which history DeepSeek restored. With **Manual connect**, use the browser popup's bridge URL `http://127.0.0.1:43127` (or the configured VS Code port), enter the displayed one-time code, and select **Pair with VS Code**.
5. Use **Check status** in the popup to distinguish pairing from page/input readiness. A task locates or opens the saved URL and checks its URL and chat input before submitting. Run **DeepSeek Agent: Diagnose Bridge** from the VS Code Command Palette for bridge/pairing diagnostics.

With **deepseekCodeAgent.autoConnect** enabled (the default), a pairing established with the one-time code is restored using the secure token in VS Code SecretStorage and the saved browser-extension origin. The bridge rejects automatic pairing from any other extension and does not allow automatic pairing before the one-time-code pairing. Existing installations will need to pair once again after this security update. Manual mode does not use the saved pairing after restart; switching Auto connect back on restores it without requiring another code. Reinstalling or clearing browser-extension storage may require a new pairing. Browser-side polling resumes automatically while paired. The VS Code **New** action archives the local conversation, opens DeepSeek's new-chat page in the paired browser, and starts a fresh local session. The first prompt creates the website conversation; after its response, the extension saves DeepSeek's actual conversation URL for following tasks.
Conversation history survives an extension-host restart. An in-flight task is not resumed automatically; on restart the extension records that it was interrupted and asks you to review workspace changes and resubmit it.

## Safety and behavior

- Ordinary conversational prompts that do not appear to need project context are sent to DeepSeek as entered, without a workspace scan, file inventory, or agent-protocol preamble. Project-specific questions and coding tasks still collect relevant workspace context. Files explicitly named in a project request are prioritized and included in full when they pass workspace exclusions and size limits; ambiguous duplicate basenames are not guessed.
- Coding tasks use `deepseekCodeAgent.responseMode`, which defaults to `python`: normal DeepSeek responses are displayed verbatim. For a code change, the prompt asks DeepSeek to return a Python script only in a fenced block labeled `fix.py`; the extension replaces or creates only the workspace-root `fix.py`, shows its VS Code diff, asks for approval, and then runs it with the configured interpreter. On Windows, the default `python` setting uses the Python launcher (`py -3`) when available, avoiding the Microsoft Store app-execution alias. Existing `fix.py` contents are backed up before replacement. A script runs with the user's normal operating-system permissions and can access files outside the workspace or run other programs; it is not sandboxed, and its other effects cannot be undone by restoring `fix.py`. A failed script may have partially changed files. Select `structured` to use the validated JSON file-operation protocol and its path/hash checks instead. Read-only overview scans remain staged and cannot execute scripts in either mode; their final answer follows the selected response mode.
- In structured mode, model output is parsed as versioned JSON. A complete JSON object can be extracted from surrounding prose, but malformed/truncated output is never repaired heuristically or partially applied; up to three complete correction attempts are requested, and an identical invalid response stops the repair loop early. Structured-mode overview summaries may be up to 30,000 characters to support detailed read-only scans. Duplicate paths, missing fields, unsupported operations, and unsafe relative paths are rejected before execution.
- Workspace context prioritizes project instructions, task-related source/tests, the active editor, manifests, diagnostics, and task-relevant Git changes. Read-only overview, review, audit, and inspection requests use an isolated, staged scan: the agent sends a bounded root/file inventory only, then DeepSeek decides which exact inventory paths to inspect and in what order. No source files are selected or read before DeepSeek requests them. Selected source files are split into labeled, UTF-8-safe chunks when needed, with a bounded total read budget and explicit coverage reporting. The final answer follows the user's requested scope: broad project overviews explain purpose and architecture, while named-component inspections can describe source-level behavior. Repeated, out-of-inventory, unsafe, oversized, and over-budget requests are bounded and reported. Overview responses cannot apply file operations or run commands. Ordinary coding tasks retain their existing task-relevant context selection and file-request flow. Long files in ordinary coding tasks are sent as marked excerpts until the model requests full contents; unchanged context already supplied during a task is not resent. If DeepSeek incorrectly claims it cannot access workspace files or asks the user to paste a named file, the agent checks the mentioned path against the workspace and automatically supplies matching local files on a retry. Only when the needed file is not available locally does it ask the user for the contents or missing details, then resumes the original task with the reply. Context is bounded. Build output, dependency trees, caches, virtual environments, Git internals, common credential files, and user-configured globs are excluded. Secret-like assignments, common token formats, bearer tokens, URL credentials, and private-key blocks are redacted. Process environment variables are never collected.
- Python mode sends the plain-text instructions with each coding request, then supplies requested context or script output on follow-up turns. DeepSeek's normal response is shown verbatim; a materially ambiguous task can return a clarification in plain text.
- The sidebar uses a familiar VS Code chat layout with a compact conversation toolbar, scrollable transcript, persistent composer, and status/proposal controls. Approval requests appear inline above the message input with explicit **Approve** and **Don't allow** actions instead of modal approval popups. Structured file edits open VS Code diffs. Python mode always shows the `fix.py` diff and requires approval to replace/create and execute it, even in auto-apply modes. Review the script: it runs with your normal permissions and is not sandboxed. An expandable **Thinking** panel shows task progress and a concise user-facing approach summary; it does not expose hidden model reasoning. Raw protocol JSON is not displayed as an assistant message. It uses **Enter** to send and **Shift+Enter** for a newline. Approval modes do not bypass approval for `fix.py`. Errors include a retry action and retain the selected approval mode.
- In structured mode, file edits are restricted to the first workspace folder, reject path traversal and symlinks, and in review mode show VS Code diffs and require explicit approval in the chat composer. Auto modes apply creations/replacements without the diff approval step. Deletions require approval in review and safe auto modes; auto-apply everything honors the explicit mode choice and deletes without a prompt, while keeping an exact-byte backup in VS Code extension storage. Files with unsaved editor changes and binary files are refused. File changes are checked for external modifications before applying and saved through VS Code document APIs. In Python mode, only the workspace-root `fix.py` is replaced by the extension; other script effects are not restricted to that file.
- Structured-mode commands are displayed exactly and require approval in the chat composer in review mode, or in safe auto mode unless the exact command is in the trusted-command list. Auto-apply everything skips the prompt for commands accepted by validation. They run without a shell, with captured output, exit status, timeout, and cancellation. Python mode executes the approved workspace-root `fix.py` with `deepseekCodeAgent.pythonInterpreter`; commands initiated by the script are not separately inspected or approved. All local processes use the configured timeout and support task cancellation. Workspace trust remains required.
- Verification is not claimed unless commands actually exit successfully. Configure project-specific verification commands under `deepseekCodeAgent.verificationCommands`; in review mode they still require approval, and in safe auto mode they run without prompts only if each exact command is trusted. `deepseekCodeAgent.responseMode` selects Python or structured coding tasks, `pythonInterpreter` selects the interpreter, and `maxIterations`, `maxResponseBytes`, `commandTimeoutSeconds`, `contextLimitBytes`, `excludedGlobs`, and `trustedCommands` control the other task limits and policies.
- The task can be stopped from the sidebar at any time. Cancellation stops waiting for DeepSeek and terminates the active local command and its child processes; command timeouts also terminate the process tree. Already-applied approved changes are retained and reported.
- Local conversations are stored in VS Code workspace state (up to 40 current messages and 20 archived sessions). Logs avoid prompt/response content; browser bridge failures may be shown in the UI.

This is an experimental integration with a third-party website, not an official DeepSeek API or partnership. DeepSeek account, availability, site behavior, quotas, and terms remain controlled by DeepSeek. Do not send confidential data unless you are authorized to share it with that service. No CAPTCHA, access control, authentication flow, or usage limit is bypassed.

## Package and install

Build the browser extension with `npm run package:browser`, then load `extensions/browser/dist` as an unpacked extension. To package the VS Code extension:

```sh
npm run package -w deepseek-code-agent-vscode
```

This writes a `.vsix` in `extensions/vscode`; install it using **Extensions: Install from VSIX**. The VS Code extension bundles its protocol/runtime dependencies.

## Troubleshooting

- **No pairing code or port conflict:** run **DeepSeek Agent: Diagnose Bridge**. Change `deepseekCodeAgent.bridgePort` and update the popup URL if another local service owns the default port. Auto connect only skips re-pairing after the first explicit code exchange; it does not bypass initial pairing.
- **Pairing rejected:** use the newest code shown by the current VS Code extension host. The code is single-use and expires when that host restarts. The bridge accepts only `127.0.0.1`.
- **Paired but chat unavailable:** verify `deepseekCodeAgent.conversationUrl` and sign in manually in the browser. When a task starts, the extension waits for the matching page and chat input, then automatically retries navigation or reloads the page once if readiness times out. If it is still unavailable, use **Check status** and check for a DeepSeek layout change. URL and input readiness do not prove the configured conversation's contents.
- **Wrong conversation or URL rejected:** set `deepseekCodeAgent.conversationUrl` to an official HTTPS `chat.deepseek.com` conversation URL with a conversation chat ID. The agent verifies the active tab against this URL before sending anything and will reuse its tab or navigate an existing DeepSeek tab.
- **Input/response selector not found or request times out:** check for a DeepSeek site update, reload the chat page, and inspect `extensions/browser/src/adapter.ts`. Unsupported layouts fail explicitly; never paste credentials or cookies into the bridge.
- **Real-site verification:** unit tests cover URL policy, tab-selection decisions, and readiness timeout behavior only. They do not prove that DeepSeek restores a selected chat URL or exposes the expected DOM in a real signed-in session. Set the conversation URL in the VS Code sidebar, inspect the correct chat, run **Check status** from the browser popup, submit a harmless prompt, and confirm the answer appears in that same conversation before relying on the integration.
- **Workspace is not trusted:** trust the folder in VS Code before running the agent. Untrusted workspaces are refused.
- **No changes applied:** inspect the proposed diff and approval prompts. Exact search-and-replace occurrence mismatches and files edited externally are refused; ask the agent to collect the current file and regenerate its proposal.
- **Verification not performed:** approve one of the proposed verification commands or configure `deepseekCodeAgent.verificationCommands`. A model's summary alone is not treated as test evidence.

## Development checks

`npm test` runs protocol/provider-mock tests, context ranking/limit and task-prompt tests, workspace-path/secret-scan/command-safety/state tests, and browser URL persistence/tab-plan/readiness/reload-recovery tests. These are unit/mock checks, not live DeepSeek website integration tests. `npm run lint` runs TypeScript checks and ESLint; `npm run format` applies Prettier and `npm run format:check` checks formatting. Browser DOM selection and streaming behavior are isolated for focused maintenance because DeepSeek does not publish a stable DOM contract.
